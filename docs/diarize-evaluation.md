# 發言者辨識評分器

`tools/score_diarization.py` 拿**人工標註**當標準答案，替 `diarize_session` 的輸出評分：DER、JER、
代號是否被拆開或混在一起、整場前後是否一致、短句與重疊發言的表現。只用標準函式庫。

這支工具**不訂任何通過門檻**。目前沒有任何資料能支持一個數字，門檻要由維護者決定
（見 `docs/meeting-workbench-implementation.md` 的品質門檻）。

## 用法

```bash
python3 tools/score_diarization.py --ref ~/lec-samples/meeting_labels.txt --hyp <辨識結果>
```

`--hyp` 可以是：

| 形式 | 說明 |
|---|---|
| session 資料夾 | 自動讀 `diarization.current.json` 指向的那一版 `speakers.json` |
| `speakers.json` | `diarize_session` 的機器可讀產物（schema 1） |
| `.rttm` | 標準 RTTM |
| 其他 | 同 Audacity label 格式的文字檔 |

`--ref` 是 Audacity 匯出的 label（`開始<TAB>結束<TAB>P1`，秒）或 RTTM。標註規則：

- 一行是一個人的一段連續發言；同一個人停頓超過約 0.5 秒就拆成兩行。
- **重疊就讓時間範圍重疊**，不要為了避免重疊而修邊界，重疊本身就是要量的東西。
- 聽不出是誰標 `UNK`（整段不計分）。笑聲、咳嗽、椅子聲不標。
- 邊界精度 ±0.1 秒就夠，collar 會吸收這個等級的誤差。
- 請從頭手動標，不要拿辨識結果來修：那樣標註會被模型的錯誤帶著走，指標會偏好看。

| 參數 | 用途 |
|---|---|
| `--region 開始:結束` | 只在這些範圍計分，可重複。**只標了一部分音訊時必須用**，否則沒標到的地方會被算成誤報 |
| `--collar 0.25` | 邊界寬容度（見下方慣例） |
| `--check-offset` | 診斷：把辨識結果整體平移 ±1 秒，看 DER 會不會明顯變好，用來抓標註與辨識的時間軸固定偏移。**不會自動套用** |
| `--offset 秒` | 確認偏移的原因之後，把辨識結果平移這麼多再計分 |
| `--json-out 檔` | 所有數字寫成嚴格 JSON（沒有 NaN） |

退出碼：0 成功；2 輸入有問題（訊息會指出檔案與行號）。

## 慣例：和別的工具比較數字之前先確認這幾條

| 項目 | 這支工具的做法 |
|---|---|
| collar | **單側**寬度，預設 0.25 秒，等於 NIST `md-eval -c 0.25`。`pyannote.metrics` 的 `collar` 是**總寬度**，要比對它的數字請用 2 倍的值 |
| collar 繞著誰 | 只繞**參考**的發言邊界。同一個人相接的標註會先併成一段，連續說話中間不會憑空多出邊界 |
| 計分範圍 | 預設是**參考標註的範圍**（第一個到最後一個標註）；範圍外的辨識輸出忽略。部分標註請用 `--region` |
| UNK | 標成 `UNK`（不分大小寫）的區間整段不計分，並在報告裡列出秒數 |
| S00 | 辨識結果的 `S00`（無法可靠指派）視為「沒有輸出」，所以算漏報，另外列出秒數 |
| DER 分母 | 參考發言者時間（兩人同時講算兩份），即 md-eval 的定義 |
| 發言者對應 | 最大化重疊時間的匈牙利演算法；平手時 DER 與選哪個無關 |
| JER | 每位參考發言者各算一個 Jaccard 誤差再平均，**對應是另外最大化 Jaccard 得到的**，不沿用 DER 的對應。只平均「在計分範圍內有說話」的人（沒說話的人 Jaccard 是 0/0，沒有定義） |
| 排除重疊區的 DER | 只排除**參考**裡 ≥2 人同時講的區間 |

## 報告怎麼讀

- **DER** 拆成漏報、誤報、混淆。漏報高通常是短句或重疊被吃掉；混淆高才是「把人認錯」。
- **JER** 對人數估計錯誤比 DER 敏感：一個人被拆成兩群，DER 可能還好，JER 會明顯變差。
- **代號一致性**是這個功能最在意的一項：
  - *分裂*：一位參考發言者有 ≥10% 的語音落在不只一個群（同一個人拿到兩個代號）。
  - *合併*：一個群裡有 ≥10% 來自不只一位參考發言者（兩個人共用一個代號）。
  - *跨時間*：有 ≥2 個時間段各 ≥5 秒語音的發言者，他最主要對應的群前後是不是同一個。有多個
    `--region` 就比各區段；否則把計分時間對半切成前半與後半。
- **依發言長度分層**看短句表現。「≥50% 正確」指該段發言有一半以上的時間被指派給對的人。
- **重疊**：參考中 ≥2 人同時講的時間，系統有沒有也偵測到重疊、被漏掉或指派錯的比例。
  引擎每個 frame 最多分辨 2 人，≥3 人同時講預期會失敗。

**樣本太小會警告**：計分少於 300 秒，或某位發言者少於 30 秒，報告會直接標出來。
15 分鐘、約 10 人的樣本，每個人只有幾十秒語音是常態，個別發言者的 JER 請當方向性參考。

## 驗證狀態

| 層級 | 內容 | 結果 |
|---|---|---|
| Automated test | 手算得出答案的案例（完美、純混淆、純漏報、誤報、collar、重疊、UNK、S00、分裂、合併、跨時間…） | 通過 |
| Automated test | **對一份獨立寫的 10 ms 逐格實作做 250 組隨機案例的交叉比對**（DER 三項與 JER 都要一致；有效案例 >150 組） | 通過 |
| Automated test | 匈牙利演算法對窮舉解 400 組隨機矩陣 | 通過 |
| Automated test | 用 `diarize_session` 真正寫出的 session（含 manifest）餵評分器，確認 parser 與引擎產物同步 | 通過 |
| Mutation test | 在評分器植入 20 種常見計分錯誤（collar 單側寫錯、漏報誤報顛倒、分母算錯、對應最小化、單位錯等），每一個都要被測試擋下 | 20／20 被抓到 |
| **未驗證** | **與外部既有實作（`md-eval`、`pyannote.metrics`）的交叉比對。** 獨立逐格實作和主程式出自同一人，若我對 DER 的定義有共同的誤解，兩邊會一起錯 | Not tested |
| **未驗證** | 真實會議標註上的表現。目前沒有任何人工標註過的多人樣本 | Not tested |

Mutation test 的腳本不在 repo 內（它會暫時改寫評分器原始檔）。測試套件在
`tests/test_diarize_score.py`，改動評分器時請確認它仍然全過。
