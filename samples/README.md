# 範例音檔

一段約 8 分鐘的模擬課堂錄音，內容是「UNIX 的起源與檔案系統」，用來驗證整條流程
（錄音解碼 → VAD 切段 → whisper 轉錄 → 分段總結 → 筆記驗證）能不能正常跑完。

```bash
lec run 測試課 --file samples/test8min.ogg
```

跑完可以跟 `expected/` 裡的結果對照。

## 這個檔案是怎麼來的

講稿由本專案自行撰寫，是虛構的課堂內容，不是任何真實課程的錄音或逐字稿；
由作者本人照著念、用筆電麥克風錄下來，再正規化音量、轉成單聲道 Opus 24 kbps，
規格跟 lec 實際上課錄到的一樣。沒有做降噪，環境音留著才接近真實情況。

要重做：

```bash
python3 tools/make_sample.py --record           # 邊念邊錄，Ctrl+C 結束
python3 tools/make_sample.py 我的錄音.wav        # 或處理現成的錄音檔
```

念的時候用平常上課的語速就好，不用刻意咬字，念錯了停下來重講一次也沒關係——
這些停頓跟修正正好是真實課堂會有的東西。整段大約 8 分鐘。

## expected/ 怎麼看

**不要拿來當 pass / fail 的斷言。** 總結是 LLM 產生的，`summary.temperature` 不為零，
whisper.cpp 與模型版本也會變，所以每次跑出來的字句都會不一樣。對照的重點是結構：

- 逐字稿的段落數與總長是否接近（約 07:55、2 段）
- 術語有沒有抓到 `fork`、`檔案描述子`、`管線`、`inode`、`POSIX` 這類詞
- 「老師強調」有沒有抓到講稿裡那幾句（「這個期中考一定會考」「大家把它抄下來」）
- 有沒有出現 ⚠ 標記（代表術語在逐字稿裡找不到，通常是轉錄錯字造成的）

如果段落數、術語、強調句都對得上，就代表這台機器上的流程是正常的。
