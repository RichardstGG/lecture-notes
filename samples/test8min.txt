好，那我們今天開始上第一章，UNIX 的起源跟設計哲學。嗯，在講技術細節之前，我想先花一點時間講歷史，因為你如果不知道 UNIX 為什麼長成現在這個樣子，後面很多設計你會覺得莫名其妙。

好，時間回到一九六九年。那時候在貝爾實驗室，有一個叫做 Multics 的專案，這是一個很大型的分時系統計畫，目標是要讓很多使用者同時共用一台電腦。可是這個專案越做越龐大，複雜到後來貝爾實驗室決定退出。

那退出之後呢，有兩個工程師，湯普森跟里奇，他們手上剛好有一台沒什麼人在用的小型電腦。湯普森那個時候想把他之前寫的一個遊戲移植過去，結果為了移植這個遊戲，他乾脆順手寫了一個作業系統。這個系統就是 UNIX 的第一個版本。

對了，UNIX 這個名字其實是在開玩笑。Multics 的 multi 是多的意思，他們做出來的東西比 Multics 簡單很多，所以一開始叫 Unics，後來才寫成 UNIX。

我要特別強調這一點，UNIX 一開始不是什麼國家級的大計畫，它是從一個小專案長出來的。所以它的設計原則從頭到尾都是簡單。

那什麼叫簡單？這邊有一句話你們一定要記起來，叫做一個程式只做好一件事。這句話是 UNIX 哲學的核心。我們後面講 shell 跟管線的時候，會再回來講這件事。

嗯，然後到了一九七三年，發生了一件很關鍵的事情。里奇設計了 C 語言，然後他們用 C 語言把整個 UNIX 核心重寫了一遍。

這件事情為什麼重要？因為在那之前，作業系統都是用組合語言寫的。組合語言是綁死在特定硬體上的，換一台機器就要整個重寫。可是 C 語言是高階語言，只要那台機器有 C 編譯器，你把原始碼搬過去重新編譯就可以跑。

所以 UNIX 就變成第一個可以移植的作業系統。這個期中考一定會考，我再講一次，用 C 語言重寫核心，讓 UNIX 具備可移植性，這是 UNIX 能夠擴散出去最重要的原因。

好，那接下來是大學。一九七零年代中期，貝爾實驗室因為反托拉斯法的關係，不能拿 UNIX 去賣錢，所以他們用很便宜的價格把原始碼授權給大學。

這個決定的影響非常非常大。因為學生拿到的不是一個黑盒子，是完整的原始碼，可以讀、可以改、可以拿來當教材。加州大學柏克萊分校就是在這個時候開始改 UNIX，後來發展出 BSD 這一支。我們現在寫網路程式用的那套 socket 介面，最早就是從 BSD 來的。

所以你可以看到，UNIX 的擴散靠的不是行銷，是靠原始碼在大學裡面傳來傳去。這跟後來 Linux 的發展模式，其實是一樣的邏輯。

好，那我們休息一下，接下來進到第二個主題，UNIX 的檔案系統跟行程模型。嗯，剛剛講的都是歷史，接下來這一段是真的要考的觀念。

UNIX 有一個非常有名的設計原則，叫做一切皆檔案。什麼意思？就是說，在 UNIX 裡面，不只是你硬碟上的資料是檔案，你的鍵盤是檔案、螢幕是檔案、印表機是檔案，甚至網路連線也可以當成檔案來操作。

那為什麼要這樣設計？好處是介面統一。你只要學會 open、read、write、close 這四個系統呼叫，你就可以操作幾乎所有的東西。你不需要為了讀鍵盤學一套，為了寫硬碟又學另外一套。

那既然什麼都是檔案，目錄呢？目錄也是檔案。目錄這個檔案裡面存的內容，就是一張對照表，記錄這個目錄底下有哪些名字，以及每個名字對應到哪一個 inode。

那 inode 是什麼？inode 是檔案在磁碟上的身分證。它記錄這個檔案有多大、權限是什麼、什麼時候建立的、實際的資料放在磁碟的哪些區塊。這邊注意，inode 裡面沒有檔名。檔名是存在目錄裡面的，不是存在 inode 裡面。

那我們順便講一下權限。UNIX 的檔案權限分成三組，擁有者、群組、其他人，每一組有讀、寫、執行三個位元。所以你用 ls 看到的那一串 rwx，就是這九個位元。這個期末一定會考怎麼換算，你們自己回去練習。

好，這邊要介紹一個很重要的概念，叫做檔案描述子。它其實就是一個整數，是作業系統給你的一個編號，代表你現在打開的某一個檔案。

那有三個編號是固定的，你們一定要背起來。零號是標準輸入，一號是標準輸出，二號是標準錯誤。這三個在每一個行程一啟動的時候，就已經幫你開好了。

好，那講到行程。UNIX 裡面要產生一個新的行程，用的是一個叫做 fork 的系統呼叫。fork 這個字的意思是分岔。每一個行程都有一個編號，叫做 PID。

fork 的行為很特別，我要特別強調，它是把現在這個行程完整複製一份。複製出來之後，你會有兩個幾乎一模一樣的行程，一個叫父行程，一個叫子行程。

那問題來了，兩個行程長得一樣，程式怎麼知道自己是父的還是子的？答案是看 fork 的回傳值。在父行程裡面，fork 會回傳子行程的編號，是一個正整數。在子行程裡面，fork 回傳零。如果回傳負一，那就代表失敗了。

這個回傳值的設計，考試很愛考，大家把它抄下來。

那複製出來之後通常會做什麼？通常會馬上呼叫 exec，把自己整個換成另外一支程式。所以 fork 加上 exec 這個組合，就是 UNIX 啟動新程式的標準做法。

好，那最後我們回來講管線，也就是 pipe。管線的概念是這樣，我把 A 程式的標準輸出，直接接到 B 程式的標準輸入。因為剛剛講過，輸入跟輸出都是檔案描述子，所以這個接線在作業系統裡面做起來非常自然。

那在 shell 裡面，你就是打一個直的那一槓。比如說我先列出目錄，然後接給一個過濾工具，再接給一個計數工具。三個小程式串起來，就完成了一件本來要自己寫程式才能做的事。

這就是我一開始講的那句話，一個程式只做好一件事。每個工具都很小、很笨，可是因為介面統一，你可以把它們自由組合。這個組合的能力，才是 UNIX 真正強大的地方。

好，那最後提一下 POSIX。因為 UNIX 後來分裂成很多版本，互相不相容，所以就制定了 POSIX 這個標準，規範系統呼叫跟命令列工具的行為。你現在在 Linux 上面寫的程式，只要遵守 POSIX，理論上搬到 macOS 上面也可以編譯。

好，今天就先到這邊。下禮拜我們開始講 shell script，記得把今天的 fork 跟檔案描述子複習一下。
